# ADR 0008: Происхождение корпуса

Статус: принято, 2026-09-22

## Контекст

Демо-корпус должен выглядеть как настоящий, но не может быть построен на реальных внутренних документах
предприятий: обезличивание ненадёжно, а переписанный чужой регламент остаётся производным произведением.
При этом система должна работать сразу после клонирования, без ключей API и без генерации на лету.

## Решение

Материал корпуса делится по происхождению: официальные документы (НПА, унифицированные формы вроде УПД,
ТОРГ-12, М-11 — вне авторского права по ст. 1259 ГК РФ) включаются дословно, с источником и датой снимка;
структура отраслевых документов (каталоги, паспорта станков, регламенты) изучается по открытым публикациям
предприятий, а текст пишется свой; внутренние документы реальных компаний не используются ни в каком виде,
даже обезличенные. Все документы порождаются из модели мира `world/` (площадки, цеха, детали, контрагенты,
роли и т. д.) через генераторы `corpus/generators/<type>.py`; в репозиторий коммитятся и генераторы, и
отрендеренные файлы в `corpus/rendered/`.

## Альтернативы

- **Использовать обезличенные реальные документы** — отклонено: обезличивание ненадёжно, а переписанный
  чужой документ остаётся производным произведением независимо от правок.
- **Генерировать корпус на лету при каждом запуске** — отклонено: перегенерация должна давать побайтово
  одинаковые файлы (фиксированный seed), иначе оценка перестаёт быть сравнимой между прогонами; коммит
  отрендеренных файлов даёт рабочую систему сразу после клонирования, без единого ключа API.

## Последствия

Корпус воспроизводим, юридически чист и не зависит от внешних сервисов при первом запуске. Документы
согласованы между собой, потому что выведены из одной модели мира, а эталоны для оценки выводятся из неё
же, а не пишутся вручную. Платим двойным объёмом в репозитории (генераторы плюс отрендеренные файлы) и
обязанностью поддерживать `corpus/PROVENANCE.md` и линтер корпуса в актуальном состоянии при каждом
изменении `world/`.
